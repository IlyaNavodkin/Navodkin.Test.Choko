## Тестовые данные

Созданы два отдельных чистых клона с настроенными identity/upstream и общим **локальным** bare remote. Сетевых аккаунтов для этой проверки не требуется. Исходный снимок `casewright-main` для приёмки открывать не нужно.

Первый клон — скопируйте путь в folder picker:

```text
D:\repo\testoritto\.cache\acceptance-user-20261016-7f42\repo-a
```

Второй клон:

```text
D:\repo\testoritto\.cache\acceptance-user-20261016-7f42\repo-b
```

Там два кейса оплаты, вложенные шаги, заметка папки, `.order`, неизвестные YAML/Markdown-поля и `vendor.txt`. Начальные SHA256 сохранены рядом с клонами в `initial-hashes.json`. Это расходные тестовые данные; остальные репозитории не затрагивались.

Эти клоны созданы от Windows-пользователя `ilyas`; оба проверены через системный Git без `GIT_*` overrides и штатный `RepositoryService::open` без GUI. Предыдущие длинные пути принадлежат sandbox-пользователю: Git приложения отклоняет их из-за `dubious ownership`. Старые клоны сохранены без изменений. Глобальные исключения Git trust не добавлялись.

## Короткий сценарий

1. Откройте `repo-a`, выберите рабочую область и кейс. Измените title, вложенный шаг и tags, сохраните, откройте повторно. Проверьте сохранённые значения и неизменность ID.
2. Создайте и продублируйте кейс. Создайте папку, перенесите туда копию. Для папок проверьте дублирование, переименование и перенос; перед удалением проверьте список, сначала отмените, затем явно подтвердите удаление тестовой копии. Отображаемая подпись из заметки может отличаться от пути папки — путь показан отдельно.
3. Создайте прогон из кейсов, запишите fail/pass, отметки шагов и пояснение, сохраните и откройте повторно. Измените исходный кейс: снимок в прогоне должен остаться прежним.
4. В Git выберите только нужные сохранённые продуктовые файлы, сделайте commit, затем отдельно push. Закройте репозиторий, откройте `repo-b` и выполните pull: изменения должны появиться во втором клоне.
5. Измените кейс без сохранения и закройте окно: проверьте отмену выхода и возвращение к черновику, затем сохранение и выход. Для внешних изменений можно отредактировать файл тестового клона в своём редакторе: несохранённый ввод приложения не должен молча заменяться.

При проблеме запишите действие, ожидаемый результат и показанный текст ошибки. Для Git-конфликта приложение предлагает ошибку и явный безопасный abort; редактора разрешения конфликтов нет.

## Подтверждено и осталось проверить

Установка, запуск и реальные native UI-сценарии этой версии ожидают вашей приёмки. macOS build/runtime, native WebdriverIO E2E и замер 5 000 кейсов/100 прогонов пока не выполнены. Полный MVP change не объявлен завершённым и не архивирован.
