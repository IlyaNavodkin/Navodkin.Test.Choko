# Автотесты: native Rust v2

Дата: 2026-10-18. Change `add-playwright-automation`. Реализован **native-путь на Rust** для раздела «Автотесты»: контракты version 2, portable-хранилище репозитория, admission/исполнение через внешний Node, нативный импорт отчётов и узкие IPC-команды. Браузерный UX-срез остаётся в [automation-ux-preview.md](automation-ux-preview.md); этот документ описывает реальный backend и продуктовую панель.

## Что сделано

- **Контракты v2** (`src-tauri/src/services/automation/v2.rs`): `Autotest`, `CaseAutotestBinding`, `ArgumentDefinition` (string/url/ip, number с min/max, boolean, enum), `ArgumentValue` (literal | ссылка `{entryId, key}`), `EnvironmentEntry`, `InvocationSnapshot`, `Manifest`/`Report` version 2 и `Discovery`. Разрешение аргументов повторяет приоритет `schema default → autotest defaults → binding overrides → run overrides` и возвращает типизированные диагностики `REQUIRED`/`INVALID_VALUE`/`ENVIRONMENT_UNAVAILABLE`/`UNKNOWN_ARGUMENT`/`UNAVAILABLE`/`PAYLOAD_LIMIT`/`STALE`. Снимок invocation проверяется на свежесть перед запуском: изменение автотеста, привязки, значения или ревизии окружения блокирует старт (`STALE_PROFILE`).
- **Portable-хранилище** (`.testoritto/automation/`): `profiles.json`, `catalog.json` (автотесты и привязки), `environments.json`, `imports.json` (хеши применённых импортов). Запись атомарная, revision покрывает все четыре файла, устаревшая ревизия отклоняется. Machine-specific Node path и grant доверия — в app-data, как и раньше. Окружения временно живут в metadata автоматизации; перенос в native-справочник — задача change `add-repository-glossary`.
- **Исполнение**: `start` принимает `invocations: [{bindingId, runOverrides}]`, проверяет trust, принадлежность кейсов прогону, наличие и включённость привязок и совпадение с discovery-каталогом; manifest v2 с invocation-снимками публикуется в app-data и в `.testoritto/automation/runs/<hash>/<executionId>/`. Bridge запускается внешним Node с массивом аргументов, cwd репозитория, Job Object/process group containment и общим лимитом времени; `poll` отдаёт bounded-страницы результатов вместе со снимком аргументов того же invocation, `cancel` останавливает дерево процессов.
- **Отчёты**: независимая проверка version 2 (корреляция с manifest, уникальность invocation, лимиты логов/вложений) и публикация `report.json` + `junit.xml`; `save_automation_reports` копирует их в папку прогона `<run>/automation/<executionId>/` без перезаписи, без Git staging и без изменения ручных файлов.
- **Импорт** (`src-tauri/src/services/automation/import.rs`): пассивный разбор Testoritto-отчёта version 1/2, сопоставление строк с текущими привязками (`matched`/`duplicate`/`unmatched`), признаки `foreignRun` и `duplicateImport`, явное применение совпавших строк как нового execution. Playwright JSON и JUnit по-прежнему разбирает Node-парсер; независимая проверка v1/v2-контракта и сопоставление — на Rust.
- **IPC**: `read_automation`, `save_automation_profile`, `save_automation_autotest`, `archive_automation_autotest`, `delete_automation_autotest`, `save_automation_binding`, `remove_automation_binding`, `save_automation_environments`, `set_automation_trust`, `preview_automation_invocations`, `discover_automation`, `start_automation`, `poll_automation`, `cancel_automation`, `save_automation_reports`, `preview_automation_import`, `apply_automation_import`. Каждая команда проверяет caller/webview, protocol и session, mutation-команды идут через общую FIFO; права выданы отдельными permissions и перечислены в `main-capability`.
- **Bridge/reporter v2** (`tools/playwright-automation`): manifest v2 запускает **по одному процессу Playwright на invocation** с аргументами в окружении (`TESTORITTO_INVOCATION_ID`, `TESTORITTO_INVOCATION_ARGUMENTS`, `TESTORITTO_SELECTION`), reporter пишет фрагмент с `invocationId`, bridge собирает итоговый `report.json` и `junit.xml`. Хелпер `getInvocationArguments()`/`getInvocationId()` опубликован как `@testoritto/playwright-automation/invocation`. v1-путь и его проверки сохранены без изменений.
- **Продуктовая панель**: `src/automation/api/*` переведён на v2-команды, панель «Автотесты» в `RepositoryBrowserPage` работает с автотестами/привязками/окружениями, перед запуском вызывает preview и передаёт снимки в `start`, а результаты показывает по invocation.

## Проверки

- Rust: `cargo fmt --check` PASS; `cargo clippy --all-targets -D warnings` PASS; **208/208** тестов, из них 12 automation: приоритеты и диагностики аргументов, `STALE` после изменения источника, строгость v1/v2-контрактов, CRUD каталога с дублями и ревизиями, реальный Node discovery/run/poll, публикация отчётов в папку прогона и неизменность Git index, containment/таймаут, нативный импорт с идемпотентностью. Дополнительно: реальный `report-v2.json`, снятый с bridge, проходит независимую Rust-проверку, а сериализованный Rust-manifest содержит ровно те ключи, которых требует browser-safe схема.
- Инструменты: `pnpm automation:test` — **16/16**, включая два новых v2-теста с настоящим Playwright CLI: один и тот же тест выполняется дважды с разными аргументами, каждая запись несёт свой `invocationId`, `junit.xml` содержит `testoritto.invocationId`, discovery отдаёт v2-каталог.
- Frontend: `tsc --noEmit` PASS; Vitest **218/218** (22 файла), включая мигрированные `automation-api`, `automationPlan`, `AutomationPanel`; продуктовая сборка PASS; browser-регрессия **42/42**; `openspec validate --strict` 5/5.

## Ограничения

- **Native-приёмка не выполнена**: приложение на Windows/macOS с этой сборкой не запускалось, реальный прогон Playwright из UI не наблюдался; macOS-ветка containment по-прежнему не выполнялась. Задачи 2.x/3.x/4.x/5.x change остаются открытыми.
- Продуктовая панель покрывает базовый поток (профиль и доверие → discovery → привязка → запуск → результат) и не показывает аргументы, окружения, историю попыток, импорт и сохранение отчётов — этот UI есть только в UX-срезе. Панель не объявлена завершённой.
- Окружения хранятся в `.testoritto/automation/environments.json`; перенос в native-справочник с типом «Окружение» — отдельная задача связанного change.
- Импорт на Rust поддержан только для Testoritto-отчётов; Playwright JSON/JUnit требуют Node-парсера, а применение результатов в ручные Markdown-файлы прогона (`apply_automation_results`) не реализовано.
- Абсолютные artifact paths не отдаются в WebView; просмотр содержимого вложений по-прежнему требует отдельной команды.
