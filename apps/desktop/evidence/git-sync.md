# Git synchronization — 15 October 2026

Реализованы явные `git_sync` actions `pull`, `push`, `abort` через typed IPC. Renderer передаёт protocol/session, UUID подтверждения из status и enum действия; paths, URL, remote и refspec не принимаются из WebView. serde deny-unknown-fields, Zod, main-window/origin/session checks и отдельная permission `allow-git-sync` действуют на команду. Новые ошибки включены в оба frontend whitelist и RU/EN i18n.

## Behavior

Pull и push показывают подтверждение текущей ветки/upstream. Отмена не вызывает mutation; pending сериализован session mutex и single-flight guard, блокирует другую запись, смену repo/tab и native close. Незавершённый editor draft не позволяет перейти к Git. Это опора на существующие синхронные native writers и UI guard; полноценная общая flush queue/watcher ещё не реализована.

Поддерживается attached branch с существующим HEAD, единственным remote URL и upstream `refs/heads/*`, отображённым в `refs/remotes/<remote>/*`. У обоих действий требуется чистый index и working tree, включая untracked. Snapshot подтверждения проверяет HEAD/branch/index/config повторно. Push отправляет подтверждённый commit OID только в configured upstream, без force/mirror/tags/submodules. Non-fast-forward и remote/auth/network/timeout ошибки не изменяют локальные commits; после сетевого таймаута следует проверить remote, так как запрос мог успеть выполниться.

Pull делает fetch только точного upstream в соответствующий remote-tracking ref, без prune/tags/recursion, затем повторяет preflight и выполняет merge проверенного FETCH_HEAD commit: `--ff --no-autostash --no-edit --no-gpg-sign --no-overwrite-ignore`. При divergence предварительно проверяется identity; обычный merge создаёт commit, конфликт возвращает unmerged paths. Существующие ignored файлы не перезаписываются. После pull/abort native resource IDs сбрасываются, config/workspaces перечитываются и frontend каталоги обновляются. Если Git применил изменения, но новая config не читается, applied-result содержит reloadRequired; writer блокируется, предлагается проверить config и открыть repo заново.

## Safe abort

В памяти хранится ownership только merge текущей session, начатого этим pull: opaque abort token, baseline HEAD, MERGE_HEAD, index SHA256 и manifest SHA256 файлов из объединения HEAD tree и текущего index, включая отсутствующие paths. До `git merge --abort` проверяются ownership, все hashes, metadata/конфигурация и отсутствие новых активных фильтров. Внешняя правка конфликтного или удалённого baseline файла означает отказ без записи. Новые посторонние untracked файлы сохраняются. После успеха проверяются baseline HEAD, отсутствие MERGE_HEAD и чистота tracked файлов.

Abort не автоматический. При отказе или неизвестном результате дальнейшая запись/Git flow блокируются, status остаётся доступен. Принудительного восстановления, reset/clean/force и UI разрешения конфликта нет. Собственные локальные commits сохраняются. Git может частично изменить состояние при системной ошибке: приложение сообщает о необходимости внешней проверки, не обещает безусловный rollback. После перезапуска ownership не восстанавливается; существующий merge обслуживается внешним Git. Это ограничение текущего среза, а не crash recovery engine.

## Git setup and limits

Git, credential helper и SSH настраиваются вне приложения. URL/credentials/stderr не возвращаются в UI. Неинтерактивный режим использует заранее настроенный системный helper/SSH agent/keys; пароль и host-key confirmation следует подготовить внешним Git. SSH executable ищется по абсолютным PATH вне repo, command экранирован; отсутствие SSH не мешает HTTP/file transport. Разрешены https/http/ssh/git/file, custom/ext helpers запрещены. Проверки auth используют только loopback HTTP fixture; реальный GitHub/SSH server не проверялся.

Active hooks/core.hooksPath, custom SSH command/variant, signing/verification, branch mergeOptions, custom merge drivers, URL rewrites, pushurl/mirror/options, linked worktrees, shallow/sparse/split index и unsupported flags требуют внешнего Git. `.gitattributes`/`.gitmodules` в текущем или входящем tree и `.git/info/attributes` не поддерживаются. Inert global LFS config разрешён, но `check-attr filter` для затрагиваемых paths должен возвращать unspecified/unset; активные фильтры не исполняются и не обходятся молча. Credentials helpers остаются доверенной частью настроенного системного Git.

Read-only sync probes ограничены 5s и 64KiB output (diff viewer отдельно допускает 256KiB на часть); mutation/network runner — 30s на команду, output threshold 64KiB с polling. Вывод хранится только в анонимных временных handles на время операции и не логируется. Windows Job / Unix process group завершают собственные Git helpers; timeout test проверяет отсутствие отложенной записи helper. Windows attach выполняется сразу после spawn; это управление собственными процессами, не sandbox произвольного malicious helper. SHA вычисляются потоково с бюджетом 32MiB для каждого tree/manifest/index. Произвольные конкурентные внешние filesystem/config изменения не покрываются общей транзакцией Git+fs; критические snapshot проверки повторяются, при сомнении запись блокируется.
