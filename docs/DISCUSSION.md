# Решения для старта

| Решение | Статус |
| --- | --- |
| React | Обязательно |
| Windows и macOS | Обязательно |
| Работа через Git | Подтверждено ответом пользователя |

## Предложения для согласования

| Вопрос | Рекомендация | Влияние |
| --- | --- | --- |
| Desktop runtime | Electron | Переиспользование Node/Git, стандартная изоляция main/renderer |
| Первая версия | Кейсы, suites, workspaces, прогоны и Git status/commit/pull/push | Последовательный перенос основных сценариев |
| Git-конфликты | На MVP список файлов, внешний редактор, повторная проверка и abort | Встроенный структурный merge остаётся отдельной задачей; ответа пользователя пока нет |
| Формат новых repos | Тот же `.casewright/`, название продукта Testoritto | Единая совместимость; `.testoritto/` без согласования не вводим |
| Credentials | Системный Git credential helper/SSH | Нет встроенного логина GitHub/PAT-хранилища |
| Git установлен отдельно | Проверять при старте, показывать инструкцию | Не включаем Git runtime в installer MVP |
| ОС первой поставки | Windows x64; macOS arm64 и x64 | Отдельные native runners и установочные smoke-проверки |
| Язык | RU по умолчанию, EN вторым этапом | Ключи i18n с начала проекта |
| Доставка MVP | Ручные private build artifacts | Подпись, notarization и автообновление отдельным release-этапом |
| Marketing site и automated tests runner | За пределами MVP | Фокус на desktop manual testing |

## Дополнительные вопросы перед фиксацией ТЗ

1. Нужен встроенный структурный merge в первой поставке или достаточно внешнего редактора?
2. Обязательны clone, branches и stash UI сразу или достаточно открытия уже клонированного repo и работы в текущей ветке?
3. Variables (`{{today}}`), approvals и HTML отчёты переносим в MVP или после основных сценариев? Существующие поля сохраняем в любом случае.
4. Ориентир по объёму: число кейсов и размер типичного repo. Для предварительной приёмки предлагается fixture 5 000 cases и 100 runs на согласованной машине; порог скорости измерить на первом реальном срезе.
5. Какие версии Windows/macOS поддерживать и нужен ли Windows ARM64?
6. Есть ли Apple Developer credentials и сертификат Windows для публичной дистрибуции? Они не нужны для подготовки проекта.

Пункты выше не являются уже согласованными требованиями. Ответы оформляются обновлением draft proposal/design/specs/tasks до реализации зависимых частей.
