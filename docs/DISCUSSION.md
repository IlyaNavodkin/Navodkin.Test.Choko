# Решения для старта

| Решение | Статус |
| --- | --- |
| Tauri 2 + React | Основа выбрана пользователем |
| Windows и macOS | Обязательно |
| Работа через Git | Подтверждено ответом пользователя |
| Читать и сохранять формат существующих Casewright repos | Подтверждено ответом пользователя |
| UI Kit `ui/`, цвета Citadelic | Обязательно |

## Предложения для согласования

| Вопрос | Рекомендация | Влияние |
| --- | --- | --- |
| Первая версия | Кейсы, suites, workspaces, прогоны и Git status/commit/pull/push | Последовательный перенос основных сценариев |
| Git-конфликты | Ошибка с unmerged paths и явный безопасный abort текущей операции | Разрешение конфликтов и отдельный UI внешнего редактора не поддерживаются; если abort не удаётся, показать диагностику и блокировать продолжение |
| Формат новых repos | Тот же `.casewright/`, название продукта Testoritto | Единая совместимость; `.testoritto/` без согласования не вводим |
| Native backend | Rust без Node-sidecar | Node fs/Git services переписываются; UI вызывает Tauri commands |
| Credentials | Системный Git credential helper/SSH | Нет встроенного логина GitHub/PAT-хранилища |
| Git установлен отдельно | Проверять при старте, показывать инструкцию | Не включаем Git runtime в installer MVP |
| ОС первой поставки | Windows x64; macOS arm64 | Минимальные версии ОС остаются открытыми; нужны native runners и установочные smoke-проверки |
| Язык | RU по умолчанию, EN вторым этапом | Ключи i18n с начала проекта |
| Доставка MVP | Ручные private build artifacts | Подпись, notarization и автообновление отдельным release-этапом |
| Marketing site и automated tests runner | За пределами MVP | Фокус на desktop manual testing |

## Оставшиеся вопросы scope

1. Нужны ли clone, branches и stash UI в первой поставке или достаточно открытия уже клонированного repo и работы в текущей ветке?
2. Включать ли UI для variables (`{{today}}`) и approvals в MVP? Существующие поля и файлы сохраняются в любом случае.
3. Какие минимальные версии Windows/macOS поддерживать? Windows ARM64 не входит в выбранные targets первой поставки.
4. Ориентир по объёму: число кейсов и размер типичного repo. Для предварительной приёмки предлагается fixture 5 000 cases и 100 runs на согласованной машине; порог скорости измерить на первом реальном срезе.
5. Есть ли Apple Developer credentials и сертификат Windows для публичной дистрибуции? Они не нужны для подготовки проекта.

Открытые пункты выше не являются согласованными требованиями. Clone/branches/stash и расширения остаются предложенными или вне обязательного scope до решения. Разрешение начать независимый каркас уже получено; остальные ответы оформляются обновлением proposal/design/specs/tasks до реализации зависимых частей.


Отдельное решение 2026-10-16: предпросмотр отчётов прогона и недели, экспорт PDF/JSON согласованы пользователем и отслеживаются в `openspec/changes/add-run-reports/`. Browser-срез реализован и проверен; подключение реальных repository snapshots, native IPC/save и desktop-приёмка остаются открытыми. Это решение не расширяет scope variables/approvals.
