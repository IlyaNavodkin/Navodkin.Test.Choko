# Справочник: изолированный UX preview

Срез задач 1.1–1.3 change `add-repository-glossary`, 16 октября 2026. Раздел доступен четвёртым пунктом навигации в `http://127.0.0.1:1421/ux-preview.html`. Это сценарий работы с данными в памяти; продуктовый entry point, native handlers, файловый формат и реальные репозитории не изменены.

В PayFlow QA доступны примеры SLA, СБП, API и регламента возвратов с демонстрационным URL. В Mobile Banking отдельный каталог. Поиск учитывает название, альтернативные названия и описание; фильтры ограничивают тип и архив. Пустая выдача предлагает сбросить фильтры. Фильтр не сбрасывает карточку или несохранённый ввод; скрытая запись отсутствует в списке и не приписывает выделение другой строке.

Карточка читается без режима редактирования. Явные действия создают запись или открывают форму: название, тип, альтернативные названия через запятую, описание и URL. Zod проверяет обязательное название и наличие описания или URL. Непустой URL допускает только корректный HTTP(S) адрес без credentials. Новый UUID назначается при создании черновика и сохраняется при переименовании, архивации и восстановлении. Архивация сохраняет содержание; физического удаления нет.

Сохранение явно меняет только память. URL показан текстом, без автоматической загрузки документа и без действия перехода по ссылке. Видимое предупреждение поясняет сброс к fixtures при перезагрузке. Места использования, snapshot, Git-файлы и native-хранение не имитируются.

Кейсы открываются для чтения. «Редактировать» включает редактор, «Чтение» показывает текущий черновик; переключение не сохраняет и не сбрасывает его. Начальный PAY-042 содержит значение «СБП»: нажатие открывает пояснение с типом, альтернативными названиями, описанием и действием «Открыть в справочнике». Переход проходит общий dirty guard. Карточка закрывается до guard; отмена перехода оставляет чтение черновика. Закрытие карточки возвращает фокус на значение. Архивная запись остаётся читаемой; отсутствующая запись показывает диагностику. Для валидной записи технический путь не занимает карточку.

«Из справочника» доступно в rich editor, Markdown source и у каждого компактного шага. Поиск учитывает title/aliases/description; новые вставки предлагают только активные записи текущего demo repo. Выделенный текст становится подписью, иначе используется название. Вставляется обычная Markdown-ссылка вида `[СБП](../../.testoritto/glossary/<uuid>.md)`, вычисленная от текущего demo case path. Rich-вставка является отдельным undo-действием; открытие и отмена picker не изменяют текст. Source вставка заменяет только выбранный slice, сопоставляя LF offsets textarea с точным CRLF исходника; неизменённая часть не сериализуется. Source/step вставку можно отменить Ctrl/Cmd+Z; внешняя замена значения сбрасывает локальную историю этой вставки.

Reader создаёт React nodes из Markdown AST: базовый GFM, ссылки внутри bold/list/table, буквальный code. HTML и изображения остаются текстом, не загружаются. Неизвестный синтаксис и reference definitions сохраняются видимым исходником; описания карточек не открывают вложенные ссылки. Внешние адреса показываются текстом. Разрешена только ограниченная grammar glossary href; resolver сравнивает его с ожидаемым href записи текущего каталога, без fs, canonical resolve или произвольного чтения. Поэтому ссылка из PayFlow QA в Mobile Banking показывает missing. Перемещение case в другую глубину пока не переписывает href и может сделать его неразрешённым; native rewrite, usage index и исторические snapshots остаются задачами 3.1–3.2.

Новый срез покрыт frontend Vitest (чтение, draft/guard, rich undo, source CRLF/caret/undo, step, archive/missing/repo scope, HTML/code/URL) и TypeScript. Итоговые headless Chromium проверки и evidence фиксирует основной агент отдельно. Этот срез не подтверждает native/runtime или запись glossary файлов.

Редактор справочника включён в существующий общий dirty guard вместе с кейсами и прогонами. Выбор другой записи, создание, раздел навигации, смена репозитория, закрытие и перезапуск демо предлагают сохранить, отказаться от изменений или остаться. Ошибка сохранения удерживает форму и блокирует отложенный переход; readonly запрещает ввод, создание и archive/restore. Два известных демо-репозитория имеют независимые hook instances, включая каталог, selected ID, форму и фильтры; storage не используется.

Проверено исполнителем: `pnpm --filter @testoritto/desktop typecheck`; `pnpm --filter @testoritto/desktop test tests/glossaryPreview.spec.tsx tests/uxPreview.spec.tsx` — 32 теста прошли. Новые 8 тестов проверяют валидацию, создание/переименование, UUID, поиск, archive/restore, guard, failed save, readonly, фильтрацию dirty-формы, изоляцию репозиториев и перезапуск. Существующие 24 теста UX preview также прошли.

CSS предусматривает двухколоночный каталог при 760 px и 1440 px; для topbar до 1050 px заданы два явных ряда. Browser/headless Chromium, визуальная оценка, pageerrors и сетевые запросы в рамках этой задачи исполнителем ещё не проверены. Их проверяет основной агент. Native Windows/macOS, установка, IPC/fs/Git и требования следующих этапов не подтверждены этим срезом. OpenSpec tasks не отмечались выполненными.

## Main-agent verification — catalog slice

Основной агент прочитал реализацию модели, интеграции guards, schema, UI/CSS и тестов. После review уточнены подписи карточки и короткие RU ошибки полей, связанные через уникальные aria-describedby. Итоговый frontend Vitest: **169/169, 17 файлов**; TypeScript, default production build, check:ui и strict OpenSpec validation проходят. Сборка по-прежнему содержит только product index.html; mock не включён в release. Существующие build warnings use client/chunk size не устранены этим изменением.

Headless Chromium: create/invalid title/invalid URL/save/edit, stable ID при переименовании, поиск по полному названию сокращения, archive/restore, dirty navigation с cancel, failed save с удержанием draft и отказом save-and-continue, readonly, изоляция двух repo и возврат к сохранённой записи, reset при reload. Отдельно проверено доступное описание ошибки названия. В этих сценариях pageerrors и внешних HTTP(S) запросов нет.

Layout 760/1280/1440: header children в границах header/viewport, горизонтального page overflow нет. Просмотрены скриншоты каталога и формы. На срезе каталога связи из кейсов ещё отсутствовали; их следующий срез описан ниже. Данные только в памяти; usage index, snapshot, Rust writer и продуктового UI нет. Задачи 1.1–1.2 отмечены основным агентом после проверок; остальной change открыт.

## Main-agent verification — reading and references

Текущий срез 1.3: **179/179 frontend tests, 18 файлов**, TypeScript, check:ui и strict OpenSpec validation проходят. Основной агент прочитал reader, resolver, picker, rich/source insertion, guarded navigation и новые тесты; browser review выявил объединение typing+insert в одну undo-группу. Исправлены отдельные границы истории; повторный сценарий подтвердил Undo только ссылки и Redo. Дополнительный source-тест проверяет selection через CRLF и collapsed caret после вставки/redo.

В headless Chromium проверены: чтение по умолчанию без полей; no-op read/edit/read без dirty; клавиатурное открытие СБП → карточка → закрытие с возвратом фокуса → переход к нужной записи каталога; rich selection omega → API с сохранением подписи и Undo/Redo; обычный набор после ссылки не расширяет её; чтение draft и guarded переход с cancel. Source selection second → SLA и step selection after → API меняют только выбранный slice, возвращают фокус, отображаются интерактивными значениями в чтении. Picker cancel не меняет кейс.

Проверены архивное пояснение по старой ссылке и исключение архива из picker, отсутствие записи при смене repo, неисполнение HTML/img/javascript и отсутствие активной ссылки внутри code. В этих сценариях pageerrors и внешних HTTP(S) запросов нет. На 760 px picker x150/y245/460×510 в границах viewport, editor buttons не выходят за viewport, page overflow отсутствует; также просмотрены 1440 px screenshots. Search имеет видимую подсказку.
