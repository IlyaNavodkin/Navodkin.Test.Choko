# Spec Delta

## Purpose

Позволяет из результата прогона создать баг-репорт с вложениями и перенести его в трекер через копирование, сохраняя контекст того, что именно выполнялось.

## ADDED Requirements

### Requirement: Bug report entity with stable identity
Система SHALL хранить баг-репорты отдельными файлами с неизменяемым `id`, заголовком, серьёзностью, статусом (`draft | ready | exported`), описанием и вложениями, не изменяя существующие кейсы и прогоны.

#### Scenario: Create and edit report
- **WHEN** пользователь создаёт дефект, меняет заголовок и сохраняет
- **THEN** файл дефекта обновлён, `id` не меняется, кейс и прогон остаются без изменений

#### Scenario: Invalid or failed save
- **WHEN** заголовок пуст или запись завершилась ошибкой
- **THEN** система показывает ошибку, удерживает черновик и не показывает ложное сохранение

### Requirement: Creation from a run preserves context
Система SHALL создавать дефект из строки прогона с автозаполнением из **снапшота прогона**: тексты шагов, состояния проверок, комментарии к упавшим шагам, notes, тестер, дата, окружение (набор аргументов и значения) и Git-контекст (ветка, commit). Система SHALL NOT подставлять живой кейс вместо снапшота.

#### Scenario: Fail in a run
- **WHEN** пользователь создаёт дефект из упавшей строки прогона
- **THEN** дефект содержит упавшие шаги с комментариями, окружение и дату из прогона, а не из текущего кейса

#### Scenario: Case deleted later
- **WHEN** кейс удалён или переименован после создания дефекта
- **THEN** дефект сохраняет контекст и показывает неразрешённую ссылку без потери данных

#### Scenario: Duplicate creation
- **WHEN** дефект для этой пары прогон + кейс уже существует
- **THEN** система предлагает открыть существующий дефект вместо создания дубликата

### Requirement: Attachments
Система SHALL принимать изображения (png, jpeg, gif, webp) через paste, drag&drop и выбор файла, сохранять их внутри папки дефекта, проверять размер и тип и SHALL показывать GIF анимированным. Отсутствующий или изменённый файл SHALL диагностироваться.

#### Scenario: Attach screenshot and GIF
- **WHEN** пользователь вставляет скриншот и перетаскивает GIF
- **THEN** оба файла сохранены, видны в карточке, GIF анимирован

#### Scenario: Oversized or unsupported file
- **WHEN** файл превышает лимит или имеет неподдерживаемый тип
- **THEN** файл отклоняется с понятной ошибкой, существующие вложения не меняются

### Requirement: Copy for Jira
Система SHALL формировать из дефекта текст для трекера (Jira wiki markup) с заголовком, окружением, шагами, ожидаемым/фактическим результатом и ссылкой на прогон, и SHALL копировать его в буфер по явному действию. Система SHALL также предоставлять копирование изображения в буфер и открытие папки вложений; ошибка копирования SHALL быть видимой.

#### Scenario: Copy report text
- **WHEN** пользователь нажимает «Copy for Jira»
- **THEN** в буфере оказывается готовый к вставке текст, включая окружение и упавшие шаги

#### Scenario: Attach images in the tracker
- **WHEN** трекер не принимает изображения из буфера
- **THEN** пользователь может скопировать изображение отдельно или открыть папку вложений, а система явно сообщает об ограничении

#### Scenario: Copy failure
- **WHEN** буфер недоступен
- **THEN** система показывает ошибку и не утверждает, что текст скопирован

### Requirement: Bug reports in runs, cases and reports
Система SHALL показывать дефекты, связанные с прогоном и кейсом, и SHALL включать раздел дефектов в отчёт прогона (PDF/JSON) с заголовком, серьёзностью и статусом. Ссылки на удалённые сущности SHALL отображаться как stale.

#### Scenario: Run report with defects
- **WHEN** у прогона есть дефекты, экспортируется отчёт
- **THEN** отчёт содержит список дефектов и не теряет связь с прогоном

#### Scenario: Stale link
- **WHEN** прогон удалён
- **THEN** дефект остаётся читаемым, а ссылка на прогон помечена как неразрешённая

### Requirement: Drafts, statuses and safety
Система SHALL требовать явного решения при уходе из изменённого дефекта и SHALL NOT исполнять или автоматически открывать вложенные файлы и ссылки. Смена статуса SHALL быть явной.

#### Scenario: Leave dirty report
- **WHEN** пользователь уходит из изменённого дефекта
- **THEN** он может остаться, сохранить или отменить изменения

#### Scenario: Hostile description
- **WHEN** описание содержит HTML/скрипт или опасную ссылку
- **THEN** это отображается текстом и не исполняется
