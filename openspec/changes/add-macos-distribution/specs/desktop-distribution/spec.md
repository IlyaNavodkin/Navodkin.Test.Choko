# Spec Delta

## Purpose

Обеспечивает установку и работу desktop-приложения на Windows и macOS из собственных сборок, с корректным платформенным поведением, единым именем продукта и честными ограничениями.

## ADDED Requirements

### Requirement: Reproducible macOS artifact
Система сборки SHALL собирать macOS arm64-артефакт нативным раннером и публиковать `.app` внутри `.dmg` и portable zip. Сборка SHALL использовать закреплённую версию NW.js, общий staging runtime-зависимостей и SHALL падать, если ожидаемый артефакт не создан.

#### Scenario: Build a release version
- **WHEN** pipeline запускается для версии `X.Y.Z`
- **THEN** создаётся `Testoritto-X.Y.Z-mac-arm64.dmg`, наличие и размер проверены, артефакт приложен к сборке

#### Scenario: Missing artifact
- **WHEN** упаковка завершилась без `.dmg` или `.app`
- **THEN** job падает и сборка не публикуется без артефакта

### Requirement: Launch and core workflow on macOS
Установленное из DMG приложение SHALL запускаться на поддерживаемой arm64-версии macOS, открывать репозиторий через нативный picker и выполнять сценарий редактирования и сохранения кейса, включая путь репозитория с пробелами и не-ASCII символами.

#### Scenario: First run
- **WHEN** пользователь открывает DMG, переносит приложение в Applications и запускает
- **THEN** приложение стартует, находит репозиторий и открывает дерево кейсов

#### Scenario: Edit and save
- **WHEN** пользователь меняет кейс и сохраняет
- **THEN** файл на диске обновляется, статус Git отражает изменение, данные не теряются при закрытии

### Requirement: Platform-appropriate window and shortcuts
На macOS приложение SHALL использовать нативное оформление окна (traffic lights) и Cmd-акселераторы для основных команд; на Windows SHALL сохраняться текущее поведение. Управление окном SHALL NOT ломать восстановление геометрии и закрытие с незавершённой записью.

#### Scenario: macOS keyboard action
- **WHEN** пользователь выполняет основную команду сочетанием с Cmd
- **THEN** действие выполняется так же, как соответствующая команда интерфейса

#### Scenario: Close with pending save
- **WHEN** окно закрывается во время незавершённой записи
- **THEN** система не теряет черновик молча и сообщает об ошибке, если запись не удалась

### Requirement: Honest update behavior per platform
Апдейтер SHALL выбирать артефакт по текущей платформе и SHALL NOT скачивать или запускать Windows-установщик на macOS. На macOS при наличии новой версии SHALL предлагаться переход на страницу релиза, а авто-обновление SHALL оставаться явно неподдерживаемым. Если release-источник не настроен, приложение SHALL сообщать об этом, а не показывать ложную доступность обновления.

#### Scenario: Update check on macOS
- **WHEN** на macOS выполняется проверка обновления
- **THEN** приложение не пытается применить обновление автоматически и предлагает понятный путь

#### Scenario: Installed-build detection
- **WHEN** приложение работает на macOS
- **THEN** Windows-специфичные проверки установленной сборки не выполняются и не влияют на статус обновления

### Requirement: Executable build pipeline in repository root
Сборка SHALL запускаться из корня репозитория и собирать desktop-приложение в `app/`. Pipeline SHALL NOT обращаться к release/update endpoints сторонних продуктов и SHALL использовать имя продукта.

#### Scenario: Build trigger
- **WHEN** pipeline запускается вручную или по push
- **THEN** он исполняется, собирает Windows и macOS артефакты под именем продукта

#### Scenario: Missing pipeline
- **WHEN** разработчик открывает документацию по сборке
- **THEN** он находит актуальные команды и путь workflow в корне, а не удалённые файлы

### Requirement: Product identity in artifacts and UI
Видимые пользователю имена (заголовок окна, About, установщик, имена артефактов, update endpoint) SHALL использовать имя продукта Testoritto; остатки старого имени SHALL быть устранены или перечислены как известное ограничение.

#### Scenario: Installed app name
- **WHEN** пользователь устанавливает и запускает сборку
- **THEN** в заголовке окна, About и имени артефакта указано имя продукта, а не старое

### Requirement: Unsigned build is explicit
Пока подпись и нотаризация не выполнены, сборка SHALL называться unsigned, а документация SHALL описывать ожидаемое предупреждение Gatekeeper и безопасный способ запуска для внутренних проверок. Неподписанная сборка SHALL NOT объявляться готовой к публичной раздаче.

#### Scenario: Internal acceptance
- **WHEN** команда проверяет unsigned DMG на macOS
- **THEN** приложение запускается после явного подтверждения пользователя, а ограничение зафиксировано в evidence
