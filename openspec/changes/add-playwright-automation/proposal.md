# Proposal

Статус: draft для обсуждения, 2026-10-18. База — текущее приложение `app/` (NW.js + React + TypeScript).

## Why

Автотесты пишутся тестировщиком в VS Code как обычные Playwright-тесты, но в приложении их не видно: нет каталога автотестов, нельзя привязать несколько тестов к одному кейсу, запустить их из прогона с аргументами окружения (`dev`, `stage`) и сохранить результат. Пользователь подтвердил весь сценарий: каталог «Автотесты», привязки к кейсам, запуск из прогона, аргументы из справочника и участие результатов в отчёте.

## What Changes

- Новый раздел «Автотесты»: каталог автотестов, полученный **discovery** из Playwright-проекта `.ch/autotests/` (проект определяется по этой папке; открытие раздела и импорт отчётов код не исполняют).
- Идентичность теста через Playwright annotations (`testoritto.caseId`, `testoritto.automationId`, `testoritto.variantId`) — переименование файла/названия не ломает связь.
- Привязки «кейс ↔ автотест» (много-ко-многим): несколько автотестов на кейс, один автотест в разных кейсах, `enabled` и overrides аргументов.
- Типизированные аргументы автотеста с приоритетом `schema default → autotest → binding → run override`; значения можно брать из записей «Аргументы» справочника (`entryId` + `key` + revision), например `dev`/`stage`.
- Запуск из прогона: выбор привязок и набора аргументов, preview итоговых значений, запуск через внешний Node и CLI проекта с официальным JSON-отчётом как источником истины, прогресс, остановка; результат сохраняется в папку прогона и **не перезаписывает** ручные результаты.
- Повтор упавших как новый execution с `parentExecutionId`; результаты содержат attempts, статусы (включая flaky/expected), логи и вложения с лимитами.
- PDF/JSON-отчёт прогона включает раздел автотестов со снапшотом аргументов и окружения.
- Вне объёма: установка Node/Playwright приложением, provisioning браузеров, sandbox чужого кода, CI-интеграция, параллельные запуски сверх лимита.

## Capabilities

### New Capabilities

- `playwright-automation`: каталог автотестов, привязки к кейсам, аргументы, запуск и результаты в прогонах.

### Modified Capabilities

Нет.

## Impact

Новые `schemas/automation.ts`, `services/automation/*` (каталог, привязки, профили, runner, отчёты), store slice, представление раздела и панель в прогоне; терпимый импорт Playwright JSON/JUnit (соседняя линия реализации — референс контрактов); правки `RunGrid`/`RunGuide` (статус автотестов отдельно от ручного), `services/report/*`, README. Требуются справочник (`add-reference-book`) и внешний Node >= 22 с установленным в репозитории `@playwright/test`.
