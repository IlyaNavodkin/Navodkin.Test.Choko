# Design

## Context

См. proposal.md. Markdown — контракт на диске: `services/format/case.ts` сериализует секции как обычные строки, `parseCase` читает их обратно; секции Steps/Systems/Acceptance уже имеют компактные строковые контролы, а Objective и Setup body — многострочные textarea. Рендер: `utils/markdown.tsx` (React-узлы, `safeUrl` только http/https/mailto), `utils/markdown-html.ts` (HTML для PDF через `printToPdf` в скрытом окне `file://`). Записи файлов идут через `services/repo-fs.ts` (self-write) и `services/persist.ts` (debounce).

## Goals / Non-Goals

**Goals:** TipTap без потери Markdown-совместимости; изображения, которые одинаково выглядят в редакторе, просмотре и отчётах; переносы кейсов не ломают пути.

**Non-Goals:** хранение HTML/JSON вместо Markdown, ресайз/обтекание изображений, rich-текст в шагах (плотные строки сохраняем), внешние загрузки, SVG, редактор изображений.

## Decisions

1. **TipTap pinned.** Пакеты TipTap фиксируются одной версией (в проверенной на соседней линии — 3.32.0; точный список подтверждается при реализации); Markdown-расширение помечено beta, поэтому поддерживаемый набор фиксируется тестами round-trip.
2. **Markdown — внешний контракт.** Компонент принимает и отдаёт Markdown-строку; при монтировании без правок значение не меняется; Change событие сериализует Markdown в существующий draft; no-op фокус/переключение режима не делает кейс dirty.
3. **Консервативный subset + source-fallback.** Неподдерживаемый синтаксис (HTML, footnotes, math, выровненные таблицы, небезопасные ссылки) не выбрасывается: пользователь видит исходник с объяснением и может отредактировать его как текст. HTML не исполняется.
4. **Область применения.** TipTap: Objective, Setup body, Notes прогона, описания справочника и баг-репортов. Steps/Systems/Acceptance остаются компактными строковыми контролами (по UX-опыту это быстрее для тестировщика).
5. **Ассеты изображений.** Файл получает имя `<sha256>.<ext>`, пишется в `.casewright/assets/`; дубликаты не копируются повторно. Разрешены png, jpeg, gif, webp; SVG запрещён; лимит на файл (например 10 MiB) и на суммарный размер операции — fail-closed с диагностикой. Пути canonical и только внутри репозитория.
6. **Ссылка и относительность.** В Markdown пишется `![alt](относительный/путь/.casewright/assets/<sha>.<ext>)`, вычисленный от файла кейса. Перемещение кейса/съюта (та же операция, что и для ссылок справочника) пересчитывает распознанные пути изображений; при неудаче операция не оставляет половину изменений.
7. **Отображение.** В редакторе изображение — атомарный узел фиксированной высоты (миниатюра), без ручек ресайза и без перетаскивания; в чтении — `max-width: 100%` в пределах колонки; GIF анимируется. Клик открывает просмотр в увеличенном виде (lightbox) без изменения документа.
8. **Отчёты.** `markdown-html.ts` инлайнит изображение как data URI, потому что печатное окно — `file://` без доступа к файлам; отсутствующий ассет даёт видимую диагностику в отчёте, а не пустое место.
9. **Вставка.** Paste изображения из буфера, drag&drop файла, кнопка выбора файла. HTML-paste не вставляет картинки из сети; remote URL не скачивается. Неизвестный MIME → явная ошибка.
10. **Формат.** Изображение — обычная Markdown-ссылка внутри существующих секций, новых секций и полей не появляется. Файл остаётся читаемым без приложения; инструмент без поддержки изображений покажет ссылку текстом и не потеряет данные.

## Risks / Trade-offs

- Markdown-расширение TipTap beta → зафиксированный subset, round-trip тесты, source-fallback и отсутствие автоматической конвертации неизвестного.
- Бинарные файлы в Git → content-addressing и дедупликация уменьшают объём, но истории свойственен рост; лимиты фиксируются в spec.
- Правки рендера не должны ломать безопасность → только локальные ассеты, никаких сетевых загрузок, SVG запрещён.
- PDF через `file://` → обязательный inline ассетов проверяется тестом отчёта с изображением.

## Migration Plan

Порядок: зависимость и codec → компонент и интеграция в Objective/Setup → ассеты и вставка → пути при move → просмотр и отчёты. Существующие кейсы без изображений не меняются; откат — удаление `.casewright/assets` и возврат textarea в конкретном поле.
