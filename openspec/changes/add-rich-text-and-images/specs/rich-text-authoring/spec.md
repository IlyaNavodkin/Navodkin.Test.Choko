# Spec Delta

## Purpose

Даёт полноценный текстовый редактор на TipTap при сохранении Markdown как формата на диске и поддерживает изображения в текстах кейсов, прогонов, справочника и баг-репортов.

## ADDED Requirements

### Requirement: Markdown-compatible rich text editor
Система SHALL редактировать полные текстовые поля через TipTap, принимая и отдавая Markdown как внешний контракт. Система SHALL NOT записывать HTML или внутреннее JSON-представление редактора в файлы репозитория.

#### Scenario: Open and save without edits
- **WHEN** пользователь открывает секцию и не меняет текст
- **THEN** значение не меняется, кейс не становится изменённым, Markdown на диске остаётся прежним

#### Scenario: Supported formatting round-trip
- **WHEN** пользователь применяет жирный, курсив, зачёркивание, список, заголовок, inline/fenced code, ссылку или простую таблицу
- **THEN** после сохранения и повторного открытия Markdown содержит эквивалентную разметку, а представление восстанавливается

#### Scenario: Unsupported syntax
- **WHEN** в поле есть HTML, math, footnotes или другой неподдерживаемый синтаксис
- **THEN** система сохраняет его как исходный текст, не исполняет и объясняет ограничение, не теряя содержимое

### Requirement: Insert local images
Система SHALL вставлять изображения из буфера, drag&drop и выбора файла, сохранять их как общие ассеты `.ch/assets/<sha256>.<ext>` и вставлять Markdown-ссылку в позицию курсора. Система SHALL поддерживать только png, jpeg, gif и webp, отклонять SVG и файлы сверх лимита и SHALL NOT скачивать изображения по сети.

#### Scenario: Paste image
- **WHEN** пользователь вставляет скриншот из буфера
- **THEN** файл сохранён в ассеты, в текст вставлена относительная ссылка, миниатюра видна сразу

#### Scenario: Duplicate and unsupported files
- **WHEN** вставляется файл, уже лежащий в ассетах, либо SVG или слишком большой файл
- **THEN** первый переиспользует существующий ассет без копии, второй отклоняется с понятной ошибкой и не изменяет текст

### Requirement: Fixed, non-editable image presentation
Система SHALL показывать изображение в режиме редактирования как миниатюру фиксированного размера без возможности изменения размера, выравнивания или перетаскивания и SHALL показывать изображение в режиме просмотра в пределах текстовой колонки. GIF SHALL отображаться анимированным.

#### Scenario: Edit versus read
- **WHEN** пользователь переключает режимы редактирования и просмотра
- **THEN** размер и положение изображения не редактируются, а в просмотре оно показывается целиком в пределах колонки

#### Scenario: Missing asset
- **WHEN** ссылка ведёт на отсутствующий или выходящий за пределы репозитория файл
- **THEN** система показывает диагностику на месте изображения и не пытается читать внешний путь

### Requirement: Path integrity across moves
Система SHALL пересчитывать относительные пути распознанных изображений и ссылок справочника при перемещении или переименовании кейса/съюта в той же операции и SHALL NOT терять текст при частичной ошибке.

#### Scenario: Move case to another suite
- **WHEN** пользователь переносит кейс с изображением на другую глубину
- **THEN** изображение и ссылки остаются разрешёнными, текст подписей не меняется

#### Scenario: Failed move
- **WHEN** операция записи завершается ошибкой на середине
- **THEN** система сообщает об ошибке и не оставляет документ с половиной пересчитанных путей

### Requirement: Images in reports and print
Система SHALL включать изображения в HTML/PDF-отчёты, встраивая локальные ассеты в документ, и SHALL показывать видимую диагностику при отсутствующем ассете вместо пустого места.

#### Scenario: Print run report with screenshot
- **WHEN** кейс с изображением попадает в PDF-отчёт
- **THEN** изображение видно в отчёте без доступа к исходным файлам

### Requirement: Format stays plain markdown
Система SHALL сохранять кейс как Markdown + YAML front matter без изменения существующих секций; изображение SHALL оставаться обычной Markdown-ссылкой, а не отдельным блоком или бинарным встраиванием. Ассеты SHALL записываться только внутри репозитория, атомарно и с self-write-маркировкой для watcher'а.

#### Scenario: Read file without the app
- **WHEN** файл кейса открывает инструмент без поддержки изображений
- **THEN** он читает секции как обычный Markdown, показывает ссылку текстом и не теряет данные

#### Scenario: Unsafe path
- **WHEN** ссылка на изображение пытается выйти за пределы репозитория или разрешается через symlink наружу
- **THEN** ассет не читается и не записывается, операция отклоняется с диагностикой
