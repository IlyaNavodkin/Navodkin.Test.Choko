# Spec Delta

## Purpose

Пользователь просматривает отчёт выбранного прогона или недели и получает переносимый PDF либо JSON с теми же сохранёнными результатами и явными настройками содержимого.

## ADDED Requirements

### Requirement: Saved report preview
Система SHALL показывать предпросмотр выбранного прогона из сохранённых snapshot/results, со сводкой шести статусов, suites/cases и исполнителями. Предпросмотр SHALL не зависеть от фильтра строк списка и не изменять исходные данные. Несохранённый ввод SHALL защищаться save/discard/cancel до открытия отчёта.

#### Scenario: Preview complete saved run
- **WHEN** пользователь открывает отчёт выбранного прогона при активном фильтре fail
- **THEN** отчёт содержит все сохранённые результаты прогона, а не только отфильтрованные строки

#### Scenario: Unsaved changes
- **WHEN** пользователь открывает отчёт при наличии несохранённого ввода
- **THEN** система предлагает сохранить, отменить изменения или остаться; failed save не открывает отчёт с черновиком

### Requirement: Weekly report matrix
Система SHALL позволять выбрать неделю понедельник–воскресенье, показывать только прогоны с датой в этом периоде и матрицу результатов по stable case ID. Отсутствие кейса в прогоне SHALL отличаться от not_run.

#### Scenario: Same case across runs
- **WHEN** в неделе два прогона одного stable case ID с разными заголовками
- **THEN** матрица содержит одну строку с результатом каждого прогона и подписью из snapshot, без чтения текущего кейса

#### Scenario: Empty week
- **WHEN** в выбранной неделе нет прогонов
- **THEN** показано пустое состояние, экспорт недоступен и пользователь может выбрать другой период

### Requirement: Explicit report content
Система SHALL предоставлять опцию включения заметок и пояснений ошибок. Выключенная опция SHALL исключать эти поля из предпросмотра и обоих экспортов. Доля успеха SHALL считаться pass/(pass+fail); при отсутствии verdict знаменателя отображается отсутствие значения.

#### Scenario: Toggle notes
- **WHEN** пользователь включает заметки
- **THEN** предпросмотр, PDF и JSON включают одинаковые сохранённые notes/fail notes; выключение убирает их

#### Scenario: No pass or fail
- **WHEN** прогон содержит только blocked/skipped/not_run/in_progress
- **THEN** отчёт не выдаёт процент успеха за 0 или 100 и сохраняет все шесть счётчиков

### Requirement: Offline PDF and versioned JSON
Система SHALL создавать действительный PDF с кириллицей, переносами страниц и читаемыми таблицами и JSON с schemaVersion, kind, generatedAt, периодом, options, stable IDs и результатами. Оба файла SHALL формироваться из одной фиксированной модели отчёта без сетевых шрифтов, изображений или исполнения текста данных.

#### Scenario: Export and inspect
- **WHEN** пользователь экспортирует отчёт в PDF и JSON
- **THEN** PDF читается стандартным reader, кириллица извлекается, а JSON проходит опубликованную схему и соответствует предпросмотру по данным/настройкам

#### Scenario: Long report or hostile input
- **WHEN** заголовки длинные либо данные содержат HTML, URL или управляющие символы имени файла
- **THEN** текст безопасно отображается, таблицы переносятся без потери строк, сетевых запросов нет, filename очищается

### Requirement: Export lifecycle and isolation
Система SHALL различать подготовку файла, успешную передачу на сохранение, отмену и ошибку; повторный клик во время подготовки SHALL не запускать дубликаты. Экспорт SHALL не изменять repo files, Git index, результаты или snapshots.

#### Scenario: Export failure
- **WHEN** renderer либо сохранение возвращает ошибку
- **THEN** отчёт остаётся открыт, показана понятная ошибка, повторная попытка доступна и success не отображается

#### Scenario: Browser versus native destination
- **WHEN** экспорт выполняется в browser preview
- **THEN** файл передаётся браузерному download с честным обозначением источника demo; это не объявляется подтверждённой native файловой записью

#### Scenario: Native export
- **WHEN** пользователь экспортирует в desktop
- **THEN** Rust проверяет caller/payload/session и пишет только в явно выбранный native save-dialog destination; отмена не создаёт файл

### Requirement: Colored result distributions
Система SHALL показывать в React preview и PDF общую сегментированную полосу шести статусов, подписи и точные счётчики, компактные распределения по наборам и каждому прогону недели. Семантика цветов SHALL совпадать между представлениями и использовать существующие UI Kit токены. Текст статусов SHALL оставаться читаемым на белом листе и сопровождаться цветным маркером. JSON и формулы сводок SHALL сохраняться.

#### Scenario: Mixed results and tiny segments
- **WHEN** сохранённые результаты содержат шесть статусов с существенно разными количествами
- **THEN** ширины сегментов пропорциональны количествам, все статусы и числа представлены в легенде, узкие сегменты не содержат перекрывающихся подписей

#### Scenario: No cases in distribution
- **WHEN** распределение содержит ноль кейсов
- **THEN** нет деления на ноль, показаны нейтральная полоса, подпись пустого распределения и шесть нулевых счётчиков

#### Scenario: Offline vector export
- **WHEN** пользователь экспортирует цветной отчёт
- **THEN** PDF содержит локальные векторные полосы и те же цвета/числа, сохраняет пагинацию и не загружает внешние ресурсы
