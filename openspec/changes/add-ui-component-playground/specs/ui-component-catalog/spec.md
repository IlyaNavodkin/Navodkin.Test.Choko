# Spec Delta

## Purpose

Дать разработчику полный и удобный каталог локальной библиотеки компонентов, чтобы найти нужный публичный визуальный экспорт и перейти к его рабочему примеру.

## ADDED Requirements

### Requirement: Полный каталог визуальных экспортов

Каталог SHALL содержать все публичные визуальные экспорты библиотеки, включая составные компоненты, с точным API-именем, группой и описанием. Каждый экспорт SHALL быть связан с демонстрацией из `coverage-matrix.md`; helpers, stores, types и инфраструктурные экспорты SHALL не появляться как визуальные компоненты.

#### Scenario: Полный начальный список
- **WHEN** пользователь открывает каталог без фильтра
- **THEN** доступны все 102 визуальных экспорта текущего `ui/index.ts`, включая `MenuItem`, `PopoverTrigger`, `Tab` и все PageShell components
- **AND** список содержит точные имена экспортов, а инфраструктурные экспорты имеют отдельную классификацию только в матрице

#### Scenario: Экспорт без демонстрации
- **WHEN** проверка покрытия обнаруживает новый визуальный экспорт без записи либо неизвестный экспорт в registry
- **THEN** проверка завершается ошибкой с конкретными именами; приложение не объявляется полностью покрывающим библиотеку

### Requirement: Группировка и размещение

Интерфейс SHALL показывать sidebar слева с группами «Действия», «Формы», «Навигация», «Данные», «Обратная связь», «Layout», «Контент и media» и именами компонентов. Сверху SHALL находиться поиск, справа — выбранный экспорт, описание, варианты и controls. Группы SHALL отражать реальные API библиотеки.

#### Scenario: Выбор составного компонента
- **WHEN** пользователь выбирает `MenuSeparator` в группе «Обратная связь»
- **THEN** справа показаны его имя и описание и рабочая Menu-композиция с отмеченной ролью разделителя
- **AND** родительские экспорты остаются доступны своими именами, без ложных независимых примеров

#### Scenario: Малое окно
- **WHEN** ширина окна составляет 800 px
- **THEN** sidebar и поиск остаются доступными, controls переходят под пример, а широкая таблица прокручивается внутри своей зоны без перекрытия навигации

### Requirement: Поиск по имени и группе

Поиск SHALL фильтровать список по точному имени экспорта и отображаемому названию группы без учёта регистра и пробелов по краям. Совпадение по группе SHALL показывать все её компоненты; пустые группы SHALL скрываться. Счётчик SHALL показывать число найденных экспортов.

#### Scenario: Поиск API-имени
- **WHEN** пользователь вводит `  BUTTON `
- **THEN** список содержит все визуальные экспорты с `button` в имени и не содержит остальные
- **AND** текущий текст поиска сохраняется при выборе результата

#### Scenario: Поиск группы
- **WHEN** пользователь вводит `формы`
- **THEN** видны все компоненты группы «Формы», даже если их API-имя не содержит запрос

#### Scenario: Нет совпадений
- **WHEN** пользователь вводит строку без совпадений
- **THEN** sidebar и правая зона показывают понятное пустое состояние, число результатов 0 и действие очистки поиска
- **AND** старая демонстрация размонтируется и её эффекты очищаются

### Requirement: Детерминированный выбор

Первым выбранным экспортом SHALL быть `Button`. При фильтрации текущий выбор SHALL сохраняться, если видим; иначе SHALL выбираться первый результат в стабильном порядке группы и имени. При отсутствии результатов выбор SHALL отсутствовать. Очистка поиска SHALL сохранять видимый выбор либо выбирать `Button`, если выбора нет.

#### Scenario: Открытие и повторный выбор
- **WHEN** пользователь впервые открывает каталог, затем выбирает `Slider` и повторно нажимает `Slider`
- **THEN** первоначально открыт `Button`; повторное нажатие текущего пункта не сбрасывает состояние Slider

#### Scenario: Текущий выбор исключён фильтром
- **WHEN** открыт `Slider`, а поиск оставляет только Menu-компоненты
- **THEN** выбран первый видимый экспорт в стабильном порядке и справа показана соответствующая композиция

#### Scenario: Очистка пустого поиска
- **WHEN** пользователь очищает запрос с нулём совпадений
- **THEN** восстановлен полный список и выбран `Button`

### Requirement: Keyboard и focus каталога

Поиск, sidebar и controls SHALL иметь доступные имена, видимый focus и последовательный Tab-порядок. Sidebar SHALL работать через Tab и Enter/Space без мыши, сообщать текущий выбор и иметь семантику navigation. Обновление поиска SHALL сохранять focus в поиске; выбор SHALL не переносить focus неожиданно.

#### Scenario: Навигация с клавиатуры
- **WHEN** пользователь через Tab достигает пункта `Input` и нажимает Enter
- **THEN** показан Input demo, пункт сообщает выбранное состояние, и пользователь может перейти Tab к controls и примеру

#### Scenario: Фильтрация во время ввода
- **WHEN** пользователь меняет запрос с клавиатуры
- **THEN** focus остаётся в поиске, обновлённый счётчик доступен assistive technology, скрытые пункты не остаются в Tab-порядке

### Requirement: Ширина и описание примеров

Правая зона SHALL давать таблицам, дереву, SplitPane и PageShell достаточно места для рабочих композиций. На 1280 px sidebar SHALL занимать примерно 240–280 px, controls — отдельную зону около 240–320 px либо строку под примером; демонстрация SHALL использовать оставшуюся ширину. У каждого примера SHALL быть описание поведения, доступные controls и действие сброса.

#### Scenario: Широкий пример
- **WHEN** пользователь открывает Table или PageShell в окне 1280×800
- **THEN** пример использует широкую рабочую область, колонки и actions читаются, длинный контент имеет локальную прокрутку

#### Scenario: Длинное имя и контент
- **WHEN** показан длинный export name или fixture с длинным текстом
- **THEN** имя и описание остаются читаемыми, controls и сброс доступны без наложения элементов
