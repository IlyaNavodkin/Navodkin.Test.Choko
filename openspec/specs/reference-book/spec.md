# reference-book Specification

## Purpose
Раздел «Справочник» хранит описания и ссылки, а также именованные наборы значений для автотестов, позволяет использовать записи в текстах приложения и сохраняет смысл исторических прогонов.

## Requirements

### Requirement: Reference entries with stable identity
Система SHALL предоставлять записи видов `link` и `arguments` с неизменяемым `id`, названием, альтернативными названиями, Markdown-описанием и признаком архива. Для `link` SHALL поддерживаться необязательный HTTP(S) URL; для `arguments` — типизированные значения `key → value`.

#### Scenario: Create and edit entry
- **WHEN** пользователь создаёт валидную запись и явно сохраняет её, затем меняет название
- **THEN** запись доступна в каталоге и поиске, а её `id` и файл не меняются

#### Scenario: Invalid entry
- **WHEN** название пусто, либо отсутствуют и описание, и URL, либо URL имеет небезопасную схему, либо у `arguments` дублируются ключи
- **THEN** система показывает ошибку поля, удерживает черновик и не заменяет сохранённую запись

### Requirement: Argument sets are typed and non-secret
Система SHALL хранить значения набора `arguments` с фиксированным типом (string, number, boolean, url, enum) и SHALL отклонять неизвестные типы, дубликаты ключей и пустой список вариантов для enum. Система SHALL предупреждать, что пароли и токены в значениях не хранятся.

#### Scenario: Reusable dev/stage values
- **WHEN** пользователь создаёт наборы `dev` и `stage` с ключами `host`, `baseUrl`, `retries`
- **THEN** в карточке видны ключи, типы и значения, а потребитель (автотесты, отчёты) может сослаться на конкретный ключ

#### Scenario: Type mismatch on read
- **WHEN** значение в файле имеет тип, не соответствующий объявленному, или файл повреждён
- **THEN** запись читается как невалидная с диагностикой, существующий файл не перезаписывается

### Requirement: Insert and read references in text
Система SHALL вставлять запись `link` в текстовое поле как обычную Markdown-ссылку на файл записи и SHALL отображать её в режиме чтения как пояснение. Неразрешённая или архивная ссылка SHALL оставаться читаемым текстом с диагностикой. Система SHALL NOT выполнять автозамену слов.

#### Scenario: Insert and read reference
- **WHEN** пользователь выбирает запись в picker «Из справочника» в редактируемом поле
- **THEN** в позицию курсора вставляется Markdown-ссылка, а в режиме чтения она открывает карточку записи с описанием и URL

#### Scenario: Missing or foreign reference
- **WHEN** ссылка ведёт на отсутствующий файл, архивную запись или путь вне `.casewright/glossary` текущего репозитория
- **THEN** система показывает диагностику, не читает посторонний файл и не теряет текст кейса

#### Scenario: Reference inside code
- **WHEN** такой же текст ссылки находится внутри code-блока
- **THEN** он не считается использованием записи и не становится интерактивным

### Requirement: Run snapshots keep history immutable
Система SHALL фиксировать использованные записи справочника и выбранный набор аргументов вместе с прогоном (id, revision, название, URL, описание, resolved values). Последующая правка или архивация записи SHALL NOT менять ранее созданный прогон.

#### Scenario: Definition changes after run creation
- **WHEN** запись отредактирована после создания прогона
- **THEN** прогон показывает прежнее пояснение и значения из снапшота и не подставляет текущую запись

#### Scenario: Incomplete snapshot
- **WHEN** кейс прогона содержит неразрешённую ссылку
- **THEN** создание прогона показывает проблему до записи и не скрывает отсутствие пояснения

### Requirement: Compatible storage and no-write open
Система SHALL хранить справочник отдельными Markdown-файлами в `.casewright/glossary/` и SHALL NOT изменять существующие кейсы и прогоны при открытии репозитория. Запись SHALL быть атомарной, оставаться внутри репозитория (canonical path, без symlink-выхода) и не терять неизвестное содержимое файла.

#### Scenario: Open existing repository
- **WHEN** открывается репозиторий без `.casewright/glossary/`
- **THEN** файлы не создаются и не меняются, а справочник показывает пустое состояние

#### Scenario: Stale or externally changed document
- **WHEN** файл записи изменён извне между чтением и сохранением
- **THEN** запись отклоняется с диагностикой, черновик сохраняется для повторного решения

### Requirement: Draft protection and errors
Система SHALL разделять черновик и сохранённую запись и SHALL требовать явного решения при переходе из изменённой записи, смене раздела, репозитория или закрытии. Ошибка записи SHALL удерживать черновик и SHALL NOT показывать ложное сохранение.

#### Scenario: Leave dirty entry
- **WHEN** пользователь переходит из изменённой записи
- **THEN** он может остаться, сохранить или отменить изменения до перехода

#### Scenario: Save failure
- **WHEN** запись файла завершилась ошибкой
- **THEN** сохранённые данные не перезаписываются, а черновик остаётся доступен для повтора
